Two RNNs, one vector

A translator built from two recurrent networks. One reads the sentence and squeezes it into a single vector. The other unpacks that vector into a new sentence, one token at a time. The single vector is where it breaks, and that failure is the reason attention was invented.

Training vs. inference

Teacher forcing and exposure bias

What should the decoder get as input at step t? During training we know the right answer, so we can feed it the true previous token. At inference there is no answer key, so it has to eat its own previous prediction. Below, the model makes one mistake at step 2. Toggle the mode and see what happens next.

In the lesson's training loop, teacher_forcing_ratio is the probability of feeding the true token at each step. Start at 1.0, then anneal toward ~0.5 so the model practices recovering from its own mistakes. That trick is called scheduled sampling.

The failure that matters

The bottleneck: every sentence gets the same 8 numbers

The toy test from the lesson: train the model to copy its input. That's the easiest task possible, since no translation is needed. Then make the input longer. The context vector never gets bigger.

Picking tokens at inference

Greedy vs. beam search

The decoder outputs a probability for every word at each step. Greedy takes the top word and can never take it back. Beam search keeps the best k partial sentences alive and scores the whole path (multiply the probabilities). The probabilities here are made up to show the effect.

Beam width 3–5 is standard. It's the same idea as model.generate(num_beams=4) in Hugging Face, and it's still used by modern transformer encoder-decoders like BART and T5.

From picture to PyTorch

The tensor shapes

B = batch, T = source length, E = embedding size, H = hidden size, V = target vocabulary size. The decoder runs one step at a time inside a Python loop, so its time dimension is always 1.

WhereTensorShapeMeaning
Encodersrc[B, T]Token ids of the source sentence
Encoderembed(src)[B, T, E]One vector per token
Encoderoutputs[B, T, H]h₁…h_T, one per position. Ignored by plain seq2seq (attention will use them).
Handoffhidden[1, B, H]Final state h_T = the context vector. Becomes the decoder's first hidden state.
Decodertoken[B, 1]Previous token (<BOS> at first)
Decoderout[B, 1, H]New hidden state sₜ
Decoderlogits[B, 1, V]Score for every target word. Cross-entropy per step, summed over the sentence.
 
_, hidden = encoder(src)                  # keep only the last state → context vector
input_token = <BOS>
for t in range(tgt_len):
    logits, hidden = decoder(input_token, hidden)
    loss += CrossEntropy(logits, tgt[:, t])  # ignore_index=0 skips padding
    if random() < teacher_forcing_ratio:
        input_token = tgt[:, t]              # teacher forcing: true token
    else:
        input_token = logits.argmax(-1)      # own prediction
loss.backward()                              # backprop through time, through BOTH RNNs
Why this leads to attention

The fix: let the decoder look back

The encoder already computes a hidden state for every source word. Plain seq2seq throws all of them away except the last. Attention keeps them all and lets each decoder step choose which ones to read.

Key terms
Encoder
RNN that reads the source. Produces per-step states and a final context vector.
Decoder
RNN started from the context vector. Generates target tokens one at a time until <EOS>.
Context vector
The encoder's final hidden state. Fixed size, whatever the input length. The bottleneck.
Teacher forcing
Feeding the true previous token during training. Stabilizes learning.
Exposure bias
The model never practiced recovering from its own mistakes, so errors snowball at inference.
Beam search
Keep the top-k partial sequences instead of committing greedily to one token.
